You already know the journey: employee facts lead to policy matches, which become assignments. PolicyOS gives each part of that journey a place in the application.

Start with the navigation:

| Area              | What you use it for                                              |
| ----------------- | ---------------------------------------------------------------- |
| Employees         | Read employee facts, current assignments, overrides, and history |
| Policies          | Define rules and inspect versions and assignment impact          |
| Groups            | Manage explicit membership and attached policies                 |
| Approvals         | Review and execute changes that require another approver         |
| Audit log         | Investigate recorded changes and their actors                    |
| Assignment fields | Define the categories policies can assign                        |
| Access control    | Manage user accounts, roles, and data access                     |

Some destinations depend on your permissions. Overview, for example, may be available to an administrator while absent for another user. A missing action doesn't necessarily mean the feature is unavailable to your organization.

Use **Quick find**, or press **Command+K** on macOS or **Control+K** elsewhere, to search pages, actions, and lesson text. Search for “Configure assignment fields” or “Manage access” to reach those areas. When reading Learn, **Back to the app** returns you to the home page; the links in these lessons open specific application areas directly.

Before following the examples, check the application header. **Demo mode** means you are exploring sample data. Its changes are temporary, its previews are simplified, and several administrative actions are unavailable. A success message there doesn't establish that a real record was saved.

For the saved workflows in this section, use a connected training deployment with the permissions your task needs. Connected changes affect that deployment's records.

We'll return to Rachel as a full-time employee in Design. Rachel, Standard Vacation, and the other teaching records are fictional; they aren't automatically loaded into your workspace. The next lessons explain how to prepare them. Existing demo employees have their own examples and expected results.
