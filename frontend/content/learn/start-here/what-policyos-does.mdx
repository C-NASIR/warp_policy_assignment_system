## The short version

PolicyOS turns trusted workforce facts into current assignment values. An employee's state, department, employment type, start date, manager, and derived facts can make policies apply. Explicit group membership can make additional policies apply too.

For each assignment field, the engine gathers candidate values from the effective policies, resolves them according to the field's cardinality and policy priority, and then applies any manual override. The result is an assignment with an explanation—not just a value.

## Follow Avery Chen

Avery is a fictional full-time engineer in California. Several policies match Avery directly, while Engineering Access applies through an explicit group. Pay schedule accepts one value, so the higher-priority California policy wins. Application access accepts many values, so unique access values are combined.

This same example continues throughout the beginner course.

## The result is inspectable

An assignment explanation can identify the winning policy version, the facts that matched, a group origin, the selection strategy, and an override that replaced policy results. Assignment history records what was true over time; the audit log records what changed and who caused it.
