The request author cannot approve their own change. Use a different authorized user with `changes:approve` and the request-specific capability.

Execution requires an approved, unexpired request and must be performed by the approving user with `changes:execute`. Rejected, expired, executed, or stale requests expose no valid execution path.

Confirm you are signed in as the expected person, then inspect request status and available actions. If the payload needs to change, create a new preview and request.
