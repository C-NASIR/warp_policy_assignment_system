## Condition fields are inputs

A condition field exposes a trusted employee fact that a policy can test. Static examples include state, department, employee type, location, start date, and manager. PolicyOS also supports allowlisted derived facts, such as tenure and organization relationships.

A condition such as `state equals California` evaluates the employee; it does not assign California or change the employee record.

## Assignment fields are outputs

An assignment field names the result that policies produce, such as Pay schedule or Application access. Each field is created with `one` or `many` cardinality, which is fixed after creation.

Policy versions attach candidate values to assignment fields. Resolution then chooses a single winning value for a one field or retains unique values for a many field.

| Question | Field type |
| --- | --- |
| What do I know about this employee? | Condition field |
| What should the resulting assignment say? | Assignment field |
| Does this employee satisfy the rule? | Condition evaluation |
| How are competing policy outputs combined? | Assignment resolution |

Keeping the two namespaces distinct prevents a policy output from silently becoming a trusted workforce fact.
