## Two complementary timelines

**Assignment history** is a temporal record of employee outcomes. Each row records a value, source, explanation, and half-open effective interval: it includes `valid_from` and excludes `valid_to`.

**The audit log** is an append-only record of actions. An event identifies the actor, entity, action, UTC timestamp, and before/after details.

| Investigation | Start here |
| --- | --- |
| What value did this employee have at a particular time? | Assignment history |
| Which policy version or override supplied it? | Assignment history explanation |
| Who created, changed, or removed something? | Audit log |
| What did the record look like before and after the action? | Audit event payload |

Assignment history can add a row when material explanation or source evidence changes even if the visible value stays the same. The audit log may contain actions that do not correspond one-for-one with assignment rows.

For a complete investigation, use history to establish the outcome timeline and audit to establish accountability for the changes around it.
