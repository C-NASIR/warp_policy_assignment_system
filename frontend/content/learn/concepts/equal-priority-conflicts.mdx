## The conflict condition

An equal-priority conflict occurs when a `one` assignment field has different candidate values tied at the highest priority. Choosing by incidental record order would hide ambiguity, so PolicyOS stops resolution.

Two top-ranked candidates with the same value are not ambiguous. Lower-priority differences also do not conflict because a higher priority already determines the winner.

## Resolve the rule ambiguity

Inspect the candidates, then either:

- give the intentionally more specific policy a higher priority;
- adjust conditions so the policies no longer overlap unexpectedly; or
- make the policies supply the same intended value.

Preview the corrected change to verify the employee population and final selection.

A manual override does not suppress this error. Policy candidates must resolve successfully before the override layer is applied, so fix the policy conflict itself.

This behavior protects explainability: every one-field result should have a defensible selection rule, not an accidental winner.
