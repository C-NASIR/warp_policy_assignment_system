## Field-level replacement

An override targets one employee and one assignment field. After the policy candidates resolve, the active override replaces all policy-derived values for that field. For a many field, it replaces the whole resolved set rather than adding one more value.

The explanation identifies the immutable override record and the policy assignments it replaced. This provenance makes the exception visible to investigators.

## Update and removal

Changing an override retires the old source and creates a new source. Removing it retires the override and reconciles the field from current policy inputs. The prior policy result can return if it still applies.

Historical assignments continue to reference the exact source that produced them. Removing an exception therefore changes current state without rewriting the past.

## Resolution still comes first

Overrides do not conceal equal-priority conflicts. Policy resolution must succeed before the override layer can replace its result. Treat a conflict as a policy-authoring problem, not as a reason to add an exception.
