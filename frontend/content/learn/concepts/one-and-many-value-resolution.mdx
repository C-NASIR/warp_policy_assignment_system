## One-value fields select

For a field with `one` cardinality, PolicyOS ranks all candidate values by policy priority. The highest-priority value becomes the assignment.

If several candidates at the winning priority all supply the same value, the result is still unambiguous. If they supply different values, resolution reports an equal-priority conflict rather than choosing one.

For Avery's Pay schedule, Bi-weekly at priority 20 wins over Semi-monthly at priority 10.

## Many-value fields combine

For a field with `many` cardinality, PolicyOS retains every unique candidate value. Priority does not remove a different value merely because another candidate has a higher number.

For Avery's Application access, direct Security Baseline supplies 1Password and group-inherited Engineering Access supplies GitHub and Linear. The assignment set contains all three.

When more than one source supplies the same many-field value, the result contains one copy. Its recorded source is chosen deterministically: highest policy priority, then lowest policy-version ID.

## Cardinality belongs to the field

Authors do not choose one-versus-many independently in every policy. The assignment field defines the strategy, and its cardinality is fixed after creation. Review the field before reasoning about priority.
